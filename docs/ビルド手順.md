# 今回のソース・ビルド

既存リポジトリを継続した`feature/jp-passive-capture`ブランチです。前回のオーバーレイと集計を保持し、実受信モジュールを追加しました。

Windows x64、Go 1.25以上で、`jp`フォルダーから実行:

```powershell
.\build-native.ps1
```

依存ソースとライセンスは`jp/vendor`へ同梱しています。Node、Vue、WebView、Cコンパイラーはnativeビルドに不要です。実受信には別途Npcapが必要です。Npcapは再配布しません。

手動ビルド:

```powershell
go test -tags native ./...
go vet -tags native ./...
go build -tags native -trimpath -ldflags '-H=windowsgui' -o MabiDPS-JP.exe .
```

開発用の件数診断（取得は1〜60秒、内容非保存）:

```powershell
.\MabiDPS-JP.exe -capture-inventory '.\adapters.json'
.\MabiDPS-JP.exe -capture-probe '.\capture-counts.json' -adapter -1 -seconds 8 -region jp
```

`-adapter -1`はゲーム接続に合うアダプターを選びます。サンドボックスや権限によって物理アダプター・TCP一覧が見えない場合、通常のWindowsアプリとしての実行結果と区別してください。

既存PCAPのオフライン診断:

```powershell
.\MabiDPS-JP.exe -pcap-replay '.\game-only.pcap' -server-port 16000 -diagnostic-out '.\replay-counts.json'
```

これはclassic PCAPの診断機能です。PCAPNGは未対応です。対象送信元ポートは明示指定が必須で、ライブ日本版のポートが16000だと仮定しているわけではありません。ファイルにOSのプロセス所有情報はないため、利用者が適切な対象データ・ポートを選ぶ必要があります。出力は件数と状態だけです。

テストのPCAPは合成です。実ゲームの生PCAPを同梱していません。テストが通っても、日本版の実戦闘デコードが検証済みになることはありません。
