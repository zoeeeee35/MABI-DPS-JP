# 入力データ仕様（バージョン1）

入力はUTF-8のJSONオブジェクト1件です。BOMがあっても読めます。ゲームの生パケット形式ではありません。サンプルは`sample-combat.json`です。

```json
{
  "version": 1,
  "region": "jp",
  "source": "normalized-offline",
  "players": [
    {"id":"alias:1","name":"仮名プレイヤー","classId":"unknown","party":true}
  ],
  "events": [
    {"id":"hit:1","atMs":0,"type":"damage","playerId":"alias:1","skillId":"unknown:1","targetId":"alias:enemy","damage":1000,"critical":false},
    {"id":"end:1","atMs":1000,"type":"end"}
  ]
}
```

- `region`: `jp` または `tw`。地域の表示辞書を選択するだけで、通信互換性を意味しません。
- `source`: 合成データは`synthetic`、許可された方法で用意した正規化データは`normalized-offline`。
- `players`: 1〜64人。一意な仮名IDを指定します。`party:true`のプレイヤーだけがパーティ集計対象です。名前は表示用の仮名とします。
- `events`: 20000件以下、時刻は昇順（同時刻可）。IDはファイル内で重複不可。重複は無視せずエラーにします。
- `atMs`: 記録開始を0とした相対ミリ秒、0〜604800000（7日）。スキルIDやプレイヤーIDは文字列で、通信上の数値型を仮定しません。
- `damage`: 0〜1000000000の整数。負数、少数、回復はサポートしません。
- `critical`: クリティカルならtrue。入力元で確定した値のみを指定します。
- `skillId`/`targetId`: 空でないID。未確認スキルは未確認のまま表示します。敵種別・ボスを自動推定しません。
- `end`: 終了イベント。ダメージ等のフィールドは含めません。
- ファイル上限は8MB。未知フィールドや不正参照は拒否します。PCAPや他のアプリの独自履歴は読み込めません。

この仕様に合わせたファイルを作ることは、ゲーム側の取得許可を与えるものではありません。許可された入力元の仕様を確認するまでは、サンプル入力を使用してください。

## 集計規則

パーティ所属のダメージが届いた時刻に開始します。明示的な終了イベントで終了するか、最後のパーティダメージから設定時間以上経過したとき終了します。無ダメージ終了の終了時刻は最後のダメージ時刻です。そのため終了確定時に、待機時間を含んでいた途中表示のDPSが上がることがあります。

DPSは各プレイヤーまたはスキルの合計ダメージを`max(1,共通戦闘時間の秒数)`で割ります。パーティ割合は対象戦闘のパーティダメージ総量を分母にします。クリティカル率はイベント数を分母にします。回復、ペット所有者への付け替え、DoTや追加打撃の特別扱い、実ゲームの戦闘状態判定は入力元との照合が必要な未実装領域です。

## 保存形式

`data/history/*.json`は再計算に必要な入力・再生時刻・終了判定設定・対象戦闘番号を持ちます。読込時に再計算し、バージョン・形式・値を検証します。`liveVerified`はfalseです。異常終了で書き込みが途切れた履歴は読込時にスキップし、その件数を表示します。複数のアプリから同じ履歴フォルダーへの同時書き込みは未検証です。

「選択戦闘を保存」で書き出すJSONは集計済み結果で、自動履歴とは異なります。アプリの入力・履歴読込には使えません。

## 実受信実験版での追加

`region:kr`と`source:capture-experimental`を追加しました。後者は受信したイベント候補を仮名化して保存するための区別であり、解釈や実ゲーム対応の検証済みを意味しません。`liveVerified`はfalseを維持します。通常の手作りサンプルはsyntheticを使ってください。
