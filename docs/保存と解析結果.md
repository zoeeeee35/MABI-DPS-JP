# ローカルPCAPNG記録・オフライン解析

## 今回の成果と未達事項

既存MabiDPS-JPへローカルPCAPNG保存・再読込・構造診断・条件差分・削除を追加。実際の日本版ゲームで待機/通常攻撃/スキルの各30秒を記録し、保存した3ファイルを繰り返し解析できることを確認しました。実戦闘イベント抽出は0件、画面数値との照合も0件。実ダメージのリアルタイムDPS入力は未達です。

## 保存場所・範囲

本フォルダーの captures/example-session/ に保存済み。

|ファイル|パケット|ファイル容量B|記録時間（JST）|
|---|---:|---:|---|
|idle.pcapng|231|71,532|2026-10-25 04:56:49〜04:57:19|
|normal_attack.pcapng|657|134,336|04:58:03〜04:58:33|
|skill_attack.pcapng|747|186,456|04:59:04〜04:59:34|

PCAPNG本体は合計392,324B（約383KiB）。各ファイル16MiBまたは30秒で停止。3ファイルの上限は計48MiB/セッション。別起動の記録は別sessionフォルダーを作成し、保存期間による自動削除はしない。同名を上書きしない。

保存対象は開始時にMabinogiMobile.exeのPIDへ関連付けたTCP接続のうちポート16000のみ。送受信双方、ACK、パケット時刻、TCPシーケンス番号、アドレス/ポート、ペイロードを元のパケット形で保持する。PCAPNGの方向フラグも付与。実行中も最新の所有接続表へ照合し、別ポート/別タプル/他プロセスの通信を記録しない。接続表は1秒更新であり、この確認精度の限界はある。

今回、利用者のログイン済みの申告後に明示開始。ログイン/アカウント操作は依頼していない。ゲームの操作は利用者が手動実施。認証情報・秘密鍵の抽出はしないが、生パケットに機密情報が入り得るため記録はローカル限定。ネットワーク送信・アップロード機能はない。ZIP配布物とソースZIPにcapturesを含めない。

## 起動・保存・停止・削除

1. MabiDPS-JP.exe → キャプチャ設定 → 日本版とゲーム接続ありのアダプター → キャプチャ開始。
2. ゲームへログイン済みであることを確認。ログイン中は保存しない。
3. 「保存A: 待機30秒」「保存B: 通常攻撃30秒」「保存C: スキル30秒」を各条件の準備後に押す。上段のA/B/Cは従来の統計測定であり、PCAPNG保存は下段の「保存」付きボタンを使う。
4. 記録中/残り秒/件数/容量/保存先を表示。保存停止で途中停止可能。キャプチャ停止でもファイルを閉じる。30秒後は自動的にファイルを閉じるが、キャプチャ自体は明示停止するまで継続（その後のデータは保存しない）。
5. 不要な記録はキャプチャ停止後「この記録3ファイルを削除」。この起動で選んだsessionの3PCAPNGと各.pcapng.jsonだけを削除する。ごみ箱を経由しない。観測メモ・解析結果・無関係なファイルは削除しない。再起動後の過去記録は下記CLIかエクスプローラーで対象sessionを確認して削除できる。

起動時は保存OFF。新しい接続は開始時の許可リストへ自動追加しない。接続が変わった場合は停止して新しい記録を始める。保存エラー/容量上限/手動中断は.pcapng.jsonのreasonに記録。読み込み不能な部分ファイルは解析成功扱いにしない。

## 再解析

開発者側で同一3ファイルの再解析を2回実施し、comparison.jsonのSHA256が一致しました。ゲームの再操作は不要です。各ファイルはclassic PCAP/PCAPNG再生と同じTCP復元・旧形式デコーダへ入力できます。

このフォルダーでPowerShellから:

```powershell
.\再解析.ps1
```

別セッションを解析:

```powershell
.\MabiDPS-JP.exe -analyze-capture-dir '.\captures\example-session' -diagnostic-out '.\comparison.json'
```

単一ファイル:

```powershell
.\MabiDPS-JP.exe -pcap-replay '.\captures\example-session\normal_attack.pcapng' -server-port 16000 -diagnostic-out '.\normal_attack-analysis.json'
```

過去の記録3ファイルを削除（キャプチャ停止後、指定先を確認）:

```powershell
.\MabiDPS-JP.exe -delete-capture-dir '.\captures\example-session'
```

このCLIはGUIを開かず終了。Wireshark互換のPCAPNGライター/リーダーで書込・再読込を検証したが、Wiresharkアプリ自体での表示確認は未実施。

通常攻撃の受信は待機より22,065B/254データありパケット増、スキルは通常攻撃より40,697B/56データありパケット増。今回、通常攻撃の送信は待機より少なく、以前の73対12という結果はそのまま再現しなかった。送信量の増減だけで戦闘イベント所在を確定しない。

- TCP再構築後、3条件に共通する先頭8バイトの優勢パターンをメモリ内の完全一致で確認。レポートへ実バイトやハッシュは出力しない。先頭パターンが一致した数は待機110/137、通常375/391、スキル427/447。ただしTCPチャンクの区切りであり、アプリケーションヘッダーの確定ではない。
- 通常29チャンク、スキル30チャンクで、offset6のBE uint32（offset8のBE uint16でも同じ候補）に6を加えるとチャンク長へ一致。待機では3件以上の一致なし。したがって汎用フレーム長とは未確定。
- 全位置探索で複数の長さ仮説が連続する区間を検出したが、条件ごとの最上位モデルは一致しない。ゼロ値や偶然の連鎖による偽陽性を避けるため、非ゼロ長・範囲・位置・時刻を記録。フレーム形式は未特定。
- 旧開始に代えて優勢先頭8バイトを仮の開始として、旧終了まで切る実験をオフラインだけで実施。通常24区間、スキル31区間を切れたが、妥当な旧ブロックは0。通常の旧damage識別子1出現もサイズが成立せず失敗。開始シグネチャの置換だけで旧パーサーが使えるとは言えない。
- 候補フレーム本文への上限付きBrotli/gzip/zlib診断は、受信各条件96候補で展開成功0。候補境界自体が未確定なので、当該圧縮形式の不使用や暗号化の証拠ではない。gzip/zstdマジックも今回の受信で0。zstd展開、LZ4、辞書付き圧縮、可変長整数、別の長さ単位等は未検証。
- エントロピー・ゼロ比率・共通位置を出力するが、高エントロピーだけで暗号としない。圧縮/暗号/独自エンコードはいずれも未特定。
- スキルの利用者申告は約4,983。通常の数値・スキルの正確な時刻/順序は不明でobservations.jsonへ記録。730/4983の単純検索をイベント抽出成功とは扱っていない。

## 実装の根拠・解析範囲

- capture_record.go: gamePacketDirection/openLocalRecorder/write/close/deleteLocalRecordings。元の時刻/seq/方向付きパケットを保存。許可した接続以外のフィルタと容量、非上書き、削除をテスト。
- capture_replay.go: PCAP/PCAPNG自動判別、双方向フロー識別、TCP復元。EOFでは保留をflushし、欠落を隠さない。
- capture_offline.go: 連続TCPデータの全位置に対する長さ仮説探索（offset0〜12、16/32bit、LE/BE、加減算12種）、チャンク開始での長さ照合（offset0〜48）、TCPチャンク跨ぎ、相対時刻、本文候補の既知展開、優勢prefixによる旧形式比較、3条件差分。
- 構造探索は方向別最大8ストリーム・各256KiB。穴以降は連続データとして結合せず、上限以後も飛ばして再接続しない。今回の全6方向ストリームは上限未到達。最大入力64MiB/10万パケット。仮説と展開の範囲外を「非対応/未検証」と区別。
- 構造仮説/変換候補をそのままDPSへ渡さない。確認済み旧構造の合成データ→DPS→保存の既存テストは維持。

## 検証と残りの課題

40件のnative自動テスト、go vet、Windowsビルド、サンプルGUIセルフテストは成功。追加テストはPCAPNG方向/時刻/対象外除外/再生/容量/非上書き/削除、全位置構造探索と分割時刻、Brotli/gzip/zlib合成展開、prefixの非出力。実記録3ファイルを再読込・反復解析し同一結果。利用者の記録は削除せず保持。

確定できたのはローカル保存と反復解析の経路、共通prefix、旧前提の不成立まで。実ダメージを抽出するには、共通prefix以降の正しい長さ/レコード種別/変換範囲を特定する必要がある。次は保存ファイルで、部分区間だけに成立する長さ候補と、レコードの連結/分割・別のサイズ単位を調べる。暗号であれば方式と正当に利用可能な鍵/nonce等の確認が必要で、まだ暗号化と確認されていない。複数ダメージの時刻照合も不足。最終目標の実DPS取得は未達。
