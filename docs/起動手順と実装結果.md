# 日本版・実受信の暫定DPSメーター

## 現在できること

TCP16000受信 → 接続/方向別TCP再構築 → JP9ヘッダー → 0x5243/53バイト → 攻撃者/対象トークン → 暫定集計 → 既存Session/analyze → Windowsオーバーレイまで接続しました。

実ゲームの連続攻撃でDPS・累計・割合・時間が更新し、攻撃停止後に戦闘終了・自動保存されることをアプリ読み取りと利用者の返答で確認しました。単発照合UI・照合回数ゲートは実装せず、追加の単発数値聞き取りも停止しています。

この版の値は全て「暫定DPS」です。方向・回復等の種別が未確定な0x5243を含むため、確定した与ダメージ/パーティDPSとは扱いません。

## 起動して使う

1. このフォルダーのMabiDPS-JP.exeを起動。
2. 日本版ゲームにログイン済みの状態で、キャプチャ設定を開く。
3. 日本版と「ゲーム接続あり」のネットワークアダプターを選び、キャプチャ開始。
4. 敵を攻撃。最初の対象イベントから暫定DPSと累計が表示される。攻撃者は実名の代わりに「識別子1（暫定）」等で表示。
5. 対象イベントが既定5秒間来なければ終了。結果はEXEと同じ場所の data/history/ に自動保存。

単発照合や30秒測定ボタンは使う必要がありません。既存の記録/診断機能は残していますが、通常利用ではキャプチャ開始だけで動きます。生PCAPNG保存は従来どおり明示的な保存ボタンを押したときだけです。

## 表示と操作

- オーバーレイ: 識別子別DPS・暫定総ダメージ・割合、全体DPS、共通戦闘経過時間。累計降順のランキング。
- 更新: JPイベントの取り込みを100msタイマーで行い、集計は約300ms間隔（250ms以上経過時）で更新。
- リセット: 日本版を取得中ならキャプチャを継続したまま集計をリセット。リセット前に届いた未処理イベントは新しい戦闘へ入れない。
- 戦闘終了: 「無ダメージ: 5秒」ボタンで3/5/10/15秒へ変更可能。
- 最前面・不透明度・クリック透過は従来どおり。Ctrl+Alt+Oでクリック透過、Ctrl+Alt+Hで表示切替。
- クリック透過OFFでオーバーレイ内部をドラッグすると移動、端/角でサイズ変更。最小340×210。サイズ変更実装は追加済みですが、今回の実機返答はDPS更新と戦闘終了についてで、手動リサイズ自体の実機確認は別です。
- 取得設定の識別子一覧で、敵側等と確認できた識別子を「集計対象へ追加/除外」で除外可能。これは集計対象の指定であり、ゲーム内パーティ情報を取得したという意味ではない。
- 履歴は「実通信・暫定DPS」と表示。選択して再分析・保存できる。サンプルは「合成サンプル」と表示し、実通信とは区別。

## DPSと時間の定義

DPS = 対象識別子の累計暫定値 / 全体で共通の戦闘経過秒数。ゼロ除算と初撃の極端な瞬間値を避けるため最小分母1秒。最初の集計対象イベントを戦闘開始とする。途中参加も同じ戦闘時間を分母にする。

対象イベントが続く限り多段・継続ダメージを全件加算。同値の別イベントも残す。設定秒数の間隔が開いたら別戦闘。戦闘中は現在時刻までの経過で計算し、終了時には最後の対象イベントで時間を確定するため、終了検出待ちの時間は最終結果へ含めない。これは既存エンジンの仕様を維持したものです。

## イベントの区別と未確定事項

- 0x5243/53Bだけを抽出し、payload+0/+8をそれぞれ8Bの不透明な識別子、+16をuint32 LEの値として扱う。上位/下位ビットの意味や型名を推測しない。
- 内部では64bit全体を使い、同じ識別子が主体/対象のどちらに出ても同一のトークンになる。トークンはセッション内HMACで、生ID/実名は画面・保存ログへ出さない。
- 自己対象（2つの識別子が同じ）、ゼロ値、不正ID、既存エンジンの上限10億を超える値は集計しない。
- 役割を既知とした分類インターフェースでは、敵を主体とするものと、味方→味方（回復等の疑い）を除外するテストを用意。役割の自動取得はまだ実装しておらず、現時点の実用モードは未分類の識別子を暫定集計する。
- 自分/パーティ/敵の自動判別、回復とダメージの完全な自動判別、スキル名、クリティカルは未確定。未分類には被ダメージ/回復等が入り得るため、確定与ダメージへ混入させず新しいSource `capture-jp-provisional` で分離。liveVerifiedはfalseのまま。
- パーティメンバーの実機識別は未検証。複数識別子のランキング・共通時間DPS・貢献率は自動テスト済みで、実機ではソロの識別子1を確認。

## 二重計上の防止

0x4FF7はペア数の確認だけに使い、ダメージイベントを発行しない。TCP再送は既存のシーケンス番号による再構築で除く。新しい0x5243フレームには独立のイベントトークンを与え、UI/集計間で同一トークンが再度渡った場合だけ除く。同値の別フレームは削除しない。アプリケーション側に独自の重複通知があるかは未確定で、値だけによる推測除去はしない。

## 検証した事実

実測の根拠:
- 1,486: 利用者がゲーム画面/スクリーンショットで確認した申告と、05:54:38.395626の保存候補が一致。
- 673: 単発測定の候補が1件だけで、06:01:03.702571の値と利用者申告が一致。
- 632: 利用者の画面申告だけ。通信照合未完了。実装を止める条件にはしない。

保存済み実通信 → 同じJP9/既存エンジン:

|記録|対象候補数|エンジンの暫定累計|結果|
|---|---:|---:|---|
|待機|0|0|戦闘を生成しない|
|通常攻撃|103|117,614|1戦闘として終了|
|スキル|140|322,050|1戦闘として終了|

通常攻撃の最終表示は約29.4秒・暫定DPS約3,993。再生結果であり新しいライブ計測値ではありません。provisional-ui-check.jsonで既存エンジン結果・終了・履歴保存を検証し、candidate-overlay.pngは自アプリの描画だけを取得しています。

新EXEを通常起動し、実ゲームからの取得を開始。アプリ読取では、実受信戦闘2が約9.7秒・暫定累計232,562で終了し保存されたこと等を確認。利用者から「更新と戦闘終了を確認できた」との返答を受領。実受信DPSの表示記録.jsonと実機連続攻撃の確認.jsonに記録。値の全件が実ダメージであるという検証ではありません。

自動テスト48件・go vet・Windows x64ビルド・既存サンプルGUI検証成功。追加テストで、同値多段/同一イベント重複/0x4FF7ペア/再送、時間/終了/保存、複数識別子のDPS/割合、自己対象/既知役割の除外、リセット前イベントの除外を検証。単発照合UIは追加していません。

## 保存・ソース・残りの作業

戦闘履歴は data/history/。生通信とは別の正規化イベントで、Sourceと未確定属性を保持。ユーザーの実記録や履歴は配布ZIPに含めない。既存PCAPNGは変更・削除せず維持。ソースは既存リポジトリの feature/jp-provisional-dps ブランチ。

今回の到達点は、実ゲームのTCP受信から暫定DPSを表示・終了保存できることです。残りは主に役割/回復などの自動分類、実名/パーティ情報、スキル/クリティカルの識別。未確定部分を確定したメーターとは報告しません。ゲーム通信改変、注入、アンチチート操作、認証情報取得、外部送信は行っていません。
