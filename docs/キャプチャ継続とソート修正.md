# MABI DPS JP：キャプチャ継続・スキルソート修正版

## 更新内容

### キャプチャが上限で止まる問題

- 周囲のスキル使用者は識別候補として保持しますが、スキル通知だけではDPSエンジンの64人枠を消費しません。
- ダメージ通知の登録が64個の攻撃者ID、または20,000イベントに達した場合は、それまでの区間を履歴へ保存して次区間へ進みます。Npcapの取得・TCP再構築・PCAPNG記録はこの切り替えでは停止しません。
- 区間保存に失敗した場合はデータを消さず、エラーを表示します。
- 履歴には「自動保存区間」と表示します。長い戦闘が上限をまたいだ場合、複数の区間に分かれることがあります。メイン画面の記録全体は現在の集計区間の値です。全区間を永久にメモリへ保持する方式ではありません。
- 1～3分の時間指定計測は、区間切り替え前の自分のイベントを引き継ぎ、指定時間全体で集計します。
- 重複確認用IDを直近4,096件に制限し、20,000個のIDが蓄積しただけで取得が停止する条件をなくしました。TCP再送の除外は従来の再構築処理で継続します。
- 予期しない停止時は data/capture-last-stop.json に停止理由・登録数・区間切り替え数を保存します。生通信は追加保存しません。

### スキル表のソート

- 通常・クリティカル・強打・連打の％列を、回数ではなく表示している割合に基づいてソートします。
- ダメージ未取得の「—」は、昇順・降順とも末尾です。
- 同じ日本語名の行も内部キーで順序を固定し、更新のたびに並びが揺れるのを防ぎます。
- 見出しを押すたびに昇順／降順を切り替えます。選択中の見出しの矢印で確認できます。

## 更新方法

1. 通信を保存中なら「停止して保存」を押します。
2. 旧アプリを終了します。
3. 新しいZIPを別フォルダーへ展開して起動するか、既存フォルダーのEXEと配布設定を更新します。
4. 履歴とキャプチャを残す場合は data と captures を削除しないでください。更新前のバックアップを推奨します。

配布ZIPには個人の履歴・設定・PCAPNGを同梱していません。

## 検証

- スキル通知だけの200個のID、65個以上のダメージ攻撃者、20,000件を超えるイベントを使う回帰テスト。
- 15分相当の時刻を持つ連続イベントの取得継続テスト（実時間のゲームプレイ試験ではありません）。
- 区間の保存・再読込、保存失敗時のイベント保持、区間をまたぐ2分計測のダメージ合計・DPS検証。
- ％順・未取得値・同名スキルの安定順序、および実際の画面の見出しクリックによる昇降順切り替え。
- 保存済みの実通信を旧EXEと新EXEで再生し、3戦闘の合計ダメージ187,228／18,533／67,664と計測時間が一致することを確認。
- Windowsビルド、静的検査、サンプルのGUI自動テスト。

実ゲームで10分以上プレイし続けた確認は今回未実施です。再度停止する場合は data/capture-last-stop.json と画面に表示されたエラーをご確認ください。
