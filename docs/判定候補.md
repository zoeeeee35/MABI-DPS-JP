# 判定フラグ検証版

## 操作
「分析」に候補回数・割合を表示します。オーバーレイにも候補割合を表示します。「スキル」の上部に通常のみ・クリティカル候補・強打候補・連打候補・追加攻撃の統計、連打ビット不一致件数、組合せ別件数を表示します。同じ画面の「個別フラグCSVを保存」で、表示区間・選択プレイヤーのCSVをローカル保存できます。全体表示は取得セッション、現在戦闘表示はその戦闘が対象です。

CSV: Timestamp(UTC)、Attacker ID、Target ID、Damage、payload[32/33/35/40](16進)、Critical/Strong/Combo/Combo Alt Candidate、Warning。未取得の過去イベントはCSVのフラグ行に含めません。生ペイロードやアカウント情報は保存しません。Entity IDと時刻は含むため、CSVの扱いには注意してください。自動外部送信は行いません。

## 候補の定義
53バイトの0x5243を既存のJP9パーサーで抽出後、独立関数decodeDamageFlagsで解析します。
- Critical: payload[32]&0x01
- Strong: payload[33]&0x02
- Combo: payload[33]&0x04
- Combo Alt: payload[40]&0x20

複数ONはそれぞれの出現回数に加算します。各割合の分母は表示対象の取得済みダメージイベント数です。合計100%になる指標ではありません。通常のみは4候補がすべてOFFのイベントだけで、追加攻撃を除外できた確定通常攻撃数ではありません。追加攻撃は「未解析」であり、0件とは扱いません。

フラグ未取得の旧履歴は通常のみへ加算せず、未取得件数として表示します。確定クリティカル・DPS・与ダメージ・HP処理は変更しません。フラグは独立した補助情報として履歴へ保存します。既存のTCP再送除外を再利用し、フラグによる新しい重複除外やダメージ加算はしません。
