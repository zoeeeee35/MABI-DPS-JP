# 個人別DPS版：操作手順と検証結果

## 起動

このフォルダーの MabiDPS-JP.exe を起動します。外部ブラウザ、WebView2、Node.jsは不要です。実通信取得には従来どおりNpcapが必要です。旧Windows標準画面へ戻す場合は `MabiDPS-JP.exe -classic-ui` を使用します。

1. ゲームへログイン済みの状態で「取得設定」を開き、実際に使用するアダプターを選択します。
2. 日本版プロファイルでキャプチャを開始します。ログイン操作中のPCAPNG記録は避けてください。
3. 職業固有のスキルを複数回使用してください。同一IDについて同じ職業のスキルを2イベント以上観測すると、自動推定の表示対象になります。通常攻撃の汎用名だけでは職業を判定できない場合があります。
4. 「検出プレイヤー一覧」に職業・セッション内の仮名短縮ID・暫定DPS・累計・割合を表示します。同じ職業でも内部の完全な識別子で分離します。表示用6桁IDだけでは集計しません。
5. 「オーバーレイ」で表示切替・クリック透過・透明度を変更できます。Ctrl+Alt+Oでクリック透過、Ctrl+Alt+Hで表示切替です。
6. 最後の対象イベントから既定5秒で戦闘終了とし、data/historyへ保存します。

## 未識別・手動設定

「検出プレイヤー」→「表示対象・職業・敵・所有者を設定」を開きます。受信候補・対象候補はこの一覧に保持されます。

- 自分、PTメンバー、検出プレイヤー・PT外、敵・NPC、召喚物、未識別を指定できます。正式なPT所属の自動判定ではありません。
- 職業が不明でも、確認できたプレイヤーを手動で「検出プレイヤー・PT外」にすれば表示できます。空の職業は「職業不明」と表示します。
- 非表示にしたいIDは手動で「未識別」に設定します。この手動分類をスキル推定が勝手に上書きすることはありません。
- 表示対象は自分のみ、PTメンバーのみ、自分＋PTメンバー、検出プレイヤー一覧から選択します。標準は検出プレイヤー一覧です。PT外プレイヤーが含まれ得ます。
- 対象を厳しく限定する場合は「敵・NPC指定の対象のみ」に変更し、対象IDも敵・NPCへ指定してください。
- 標準の「対象未識別も含む（暫定）」は、表示対象の攻撃元から、まだ分類できていない対象への候補値を含みます。対象を敵と確定したという意味ではありません。
- 召喚物は所有者IDを指定できた場合だけ、その表示対象プレイヤーへ帰属させます。所有者不明は加算しません。
- 「対応付けを保存」はローカルJSONです。同じ取得セッションの対応付けだけ再読込できます。別のキャプチャやPCAP再読込では仮名IDが変わるため、自動流用しません。エリア移動後のID再利用は未検証です。エリアやゲームを再起動したらキャプチャを停止・再開始し、指定を見直してください。

## 保存済み実通信で確認した構造

独自のGo実装で、読み取り専用・ローカル解析しました。生パケットや認証情報を外部送信していません。

- 0x5243：53バイトの本文の+0に8バイトの識別子候補、+8に対象候補、+16に32ビットの数値候補。
- 0x1D4F8：本文+0の8バイトID、+8の32ビット文字列バイト長、+12以降のUTF-16LEスキル名。観測名には IceMage_CrystalEdge_01、IceMage_IceBarrier、SwordMaster_SwiftAttack、SwordMaster_SwordDance 等があります。
- 複数の独立した保存記録で、0x1D4F8の先頭8バイトが0x5243の先頭8バイトと一致しました。本文末尾にも別のIDらしい値が現れるため、任意の位置の一致や下位4バイト一致を紐付けには使用しません。
- 旧韓国版の公開Pythonは、1432形式、本文先頭4バイトのID、+24以降のスキル文字列を使用しています。日本版の上記位置はそのまま移植せず、保存データを根拠に実装しました。公開HTMLの職業プレフィックス分類の考え方を参考にし、コードや非公開アセットはコピーしていません。
- 職業名は config/jp-class-prefixes.json で変更できます。観測していない職業プレフィックスについて日本版の実動作を確認したわけではありません。

参考：https://github.com/teto-ri/Mobinogi_Meter の Decomplie_new_base/mobi_capture.py、mobi_meter AUTO_Detect_Addon.html。

## 検証結果

- 自動テスト：67項目成功、失敗0（サブテストとローカルPCAPNG検証を含む）。Windowsネイティブビルド・go vet・既存サンプルGUI再生も成功。
- 同職業の異なるID、被攻撃側との逆転、未知の攻撃元、既知プレイヤー同士、所有者指定の召喚物、所有者不明、表示除外、職業推定競合、手動補完を自動テストしました。合成データによる分類テストは、ゲーム上の全種別を検証したことにはなりません。
- local-analysis/example-session/skill_attack の再生：IceMageの職業文字列12イベントを観測。既存の候補累計322,050を氷結術師のIDへ対応付け。
- provisional-dps/example-session-b/skill_attack の再生：IceMage10イベント、SwordMaster5イベントを観測。アプリで氷結術師37ダメージ候補・累計33,112、別IDの剣術士0ダメージを表示。戦闘結果1件の保存を確認。
- 剣術士はこの記録ではスキルのみ検出され、対応する0x5243の与ダメージを確認できませんでした。実データで二人分の非ゼロDPSが取得できた、とは扱いません。
- player-main.png、candidate-overlay.png は同じアプリ描画処理から作った、自アプリだけの画面です。実ウィンドウでもダーク画面の起動を確認しました。
- WebView2試作版は実機で白画面を確認したため、今回のEXEでは使用しません。試作ソースは残していますが完成機能には含めません。設定・詳細診断は従来のネイティブ補助画面を維持しました。

## 残る制約

職業のプレフィックスとID一致は有力な手掛かりですが、プレイヤー・敵・NPCの完全な区別を証明しません。職業を模倣するNPC、召喚物、共通スキル、職業変更もあり得ます。複数職業が衝突したIDは自動採用を止め、未識別へ戻します。

未知の攻撃元、既知の敵からの攻撃、自己対象、既知プレイヤー同士のイベントはランキングへ入れません。ただし、未識別対象への回復や別イベントを完全に識別する種別フラグはまだ不明です。「敵の攻撃や回復が絶対に混入しない正式DPS」は未達です。0x4FF7は加算せず、同値の別ヒットは消しません。TCP再送の除去は既存の再構築層を維持しています。

スキル使用者の職業推定には対応しましたが、最新スキル名を時間だけで各0x5243へ割り当てる処理は入れていません。DoT、多段、召喚物の誤帰属を避けるため、スキル別ダメージは未特定表示です。正式PT名簿、自動参加離脱、全職業、125%/150%の実OS表示倍率、新しいレイドで複数人が同時に非ゼロDPSとなる実機確認は未検証です。

次は、今回のEXEで複数プレイヤーが職業固有スキルを使う場面をまとめて確認します。単発ダメージの聞き取りは不要です。表示されないIDだけ手動で補完し、問題が出た方向・スキルに絞って追加解析します。

技術的にキャプチャ可能なことと、ゲーム運営が利用を認めることは別です。利用規約・運営判断によるリスクは残ります。通信改変、注入、メモリ書換え、アンチチート回避、認証情報・秘密鍵の取得は行っていません。

手動分類は現在セッションの保存イベントを再集計します。加入・離脱の時刻別名簿は未実装で、分類変更後の再保存により別の集計結果が履歴へ残る場合があります。履歴に残った取得時点の対応付けと、現在の表示条件を区別してください。
