# Scouter Lite比較・日本版対応調査

調査日: 2026-10-25（日本時間）。今回の成果物は独立したWindowsネイティブアプリ `MabiDPS-JP.exe`。前段階のブラウザー版は検討用コードとしてリポジトリ内に残したが、今回のEXE・配布ZIPには含めない。

## 結論と優先順位

P0: 日本版で許可された入力経路を確認する。確認した公開資料からは、DPS分析に利用が認められた戦闘ログ／APIとその仕様を特定できなかった。「存在しない」と断定しているのではなく、採用できる根拠を確認できていない。そのため通信取得を実装しない。

P1: 正規化したオフラインイベントと集計を分離し、サンプル入力で開始・終了、全員共通時間のDPS、パーティ内割合、スキル別合計を確立する。

P2: ブラウザー依存を取り除き、Win32の独立ウィンドウとして半透明・最前面・クリック透過・非アクティブ化を実装する。

P3: 戦闘終了時のローカル履歴、アプリ内の再分析、JSON書き出しを接続する。

P4: 自動テスト・Windows GUI生成・実画面操作を検証する。実ゲーム接続・ゲーム上のオーバーレイ表示の検証とは区別する。

P1〜P4のオフライン範囲を実装・検証した。実ゲーム接続の完成はP0に必要な根拠が得られるまで保留。

## 3ツールの比較

| 項目 | Scouter Lite | MOGUGI | Mobinogi_Meter |
|---|---|---|---|
| 対象の根拠 | 公開ページがMabinogi Mobileの非公式分析を説明 | READMEはTaiwan regionのMabinogi、Client.exe・アルカナ体系を実装 | READMEでマビノギモバイル用と説明 |
| UI | 公開更新履歴にオーバーレイ、設定、履歴・分析への言及 | Goローカルサーバー＋Vue | Python／別配布解析器＋HTML/WebSocket |
| 取得の公開情報 | Rustパーサー・WinDivertの記載。実装詳細・日本版互換性は不明 | Npcap/pcap、Windows TCP所有PIDからClient.exeを探す | Scapyで特定TCP送信元ポートを取得し独自形式を読む |
| 日本版への流用 | 公開機能を参考にする。コード・アセットの再利用根拠なし | UI構成・集計の考え方は参考になるが、モバイル通信に適用できる根拠なし | フレーム構造自体がMOGUGIと異なる。日本版互換性未確認 |
| ライセンス | 公開ページから再利用許諾を確認できず | MIT、著作権表示を保持 | 明示的LICENSEなし、GitHub metadataもlicense:null。コードはコピーしない |

Scouter Liteの公開ページでは、設定によるオーバーレイ調整、戦闘履歴の絞り込み・並べ替え、グラフ範囲選択に連動する分析、スキルやバフの表示を確認した。本実装はそのうち、常時表示のランキング、設定の切替、履歴選択から分析という流れを参考に独自実装した。公開ページだけではアプリ内部の画面遷移・実装や取得許諾を確認できない。インストーラーの取得・実行、逆コンパイル、独自アセットのコピーは実施していない。

根拠: [Scouter Lite公式公開更新履歴](https://scouter-lite.mobi/)（v1.12.3、2026-10-17表示）。バフ／装備／区間ドラッグ分析等は今回の実装対象外。

## MOGUGIのコード上の根拠

取得した基点: `db245837fbaa003b55333556af35bf4cd254c92e`。全215追跡ファイルの構成と関連する実行経路を確認。Go側の取得・解析・イベント配信、Vue側の集計・表示・ID辞書、ビルド・ライセンスを中心に調査した。全ファイルを行単位で監査・安全性保証したという意味ではない。

- [README](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/README.md): Taiwan regionとGo/Vue、prilus/dilmatulgi由来を明記。Mobileとは記載していない。
- [pcaputil.go](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/lib/pcaputil/pcaputil.go#L130): WindowsのTCP所有PIDを列挙し、155行の`Client.exe`照合で接続を絞る。日本版モバイルのプロセス・ポートを設定変更だけで扱える証拠はない。
- [gamePacketReader.go](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/lib/packet/gamePacketReader.go): pcapでNICまたはファイルから取得。TCP再構成は`tcpReassembly.go`に分離。6バイトヘッダー、長さとフラグを検証し、`gamePacket.go`/`message.go`形式へ変換する。
- [opCode.go](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/lib/packet/opCode.go#L47): 戦闘アクションを31014 (`0x7926`) と定義。
- [combatActionPacket.go](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/lib/packet/combatActionPacket.go): EntityIdはuint64、SkillIdはuint16、ダメージはfloat32、クリティカルはHit.Optionsのbit0。日本版モバイルの値として流用していない。
- [eventPublisher.go](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/cmd/mogugi/eventPublisher.go#L992): 非Hitサブパケットから攻撃者とスキルを取り、Hitサブパケットを対象・ダメージに関連付けてEventDamageを配信。単一攻撃者という前提がある。
- [entityAppearPacket.go](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/lib/packet/entityAppearPacket.go#L56): 出現データのNameとRaceIdを読む。`cmd/mogugi/entityMap.go`で出現・消失・状態をキャッシュする。
- [mabidb.ts](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/front/src/mabidb.ts): `mabi_<region>.sqlite`内のrace、skill等のテーブルから表示名を取得。[build-data.mjs](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/front/scripts/build-data.mjs#L16)はtw/v168に固定される。
- [arcanaTable.ts](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/front/src/lib/arcanaTable.ts): スキル59xxxの範囲からアルカナを推定し、Go側`cmd/mogugi/arcana.go`にも表を持つ。モバイルの職業IDテーブルとして使える根拠はない。
- [actionCollector.ts](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/front/src/actionCollector.ts#L203): ダメージを加算し、命中とクリティカル数を収集。`countsTowardStats`で統計対象を区別する。
- [applyDamageBySkill.vue](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/front/src/components/applyDamageBySkill.vue#L1044): プレイヤーの最初〜最後の命中の差でDPSを計算し、2件未満なら0。本実装はパーティ共通戦闘時間・最小1秒を採用したため、同じ入力でも元ツールとDPSが異なる場合がある。
- [build.ps1](https://github.com/irusan-fanclub/mogugi/blob/db245837fbaa003b55333556af35bf4cd254c92e/build.ps1): VueをビルドしてGo埋込先へコピーし、`cmd/mogugi`をEXE化する。`front/package.json`のVite7等は新しいNodeを要求する。元ビルドは別途DB/アイコン生成、Npcap、アクティベーション鍵等の要素があり、日本語化だけで日本版モバイル用にはならない。
- `cmd/mogugi/license.go`、`lib/license`: アプリの認証・利用権処理。OSSのMITライセンスとは別の仕組み。元の認証を改変して接続する実装はしていない。今回のnativeターゲットはこれらをコンパイルしない。

台湾と日本で変わる可能性がある箇所は、プロセス識別、接続・フレーム仕様、opcode、圧縮・暗号化、識別子の型と値、攻撃とヒットの対応、職業・スキル・敵名、戦闘区切り。実通信サンプルがないため、どれが実際に違うかは未確定。

## Mobinogi_Meterのコード上の根拠

取得した基点: `eed9089bb4a24a69f8db349dbe4bd6eb9529362f`。

[README](https://github.com/teto-ri/Mobinogi_Meter/blob/eed9089bb4a24a69f8db349dbe4bd6eb9529362f/README.md)では、MDM_origin_baseを既存解析器のプロキシ拡張、Decomplie_new_baseをデコンパイル・復元したものと説明している。リポジトリ内の配布EXEは実行していない。

[mobi_capture.py](https://github.com/teto-ri/Mobinogi_Meter/blob/eed9089bb4a24a69f8db349dbe4bd6eb9529362f/Decomplie_new_base/mobi_capture.py#L34)ではTCP送信元16000、独自開始・終了パターン、データ種別1283/1432を定義。`parse_damage`（270行付近）は攻撃者・対象・スキル名・ダメージ・フラグ・スキルIDを読む。`parse_data`は一部ペイロードをBrotli展開し、スキル通知とダメージの対応にキューと時刻・シーケンスの近さを利用する。ここにも未確定の関連付けがあり、日本版の正しさは証明されない。これらの数値や推定ロジックはコピーしていない。

再利用候補は正規化したイベントの集計・UI概念。取得器の採用には、日本版の許可・仕様・ライセンス確認が先に必要。

## 今回の実装境界

- nativeターゲットはGo標準ライブラリとWindows標準DLLだけを使用する。HTTPサーバー、ブラウザー起動、WebView、pcap、WinDivert、ゲームプロセスへのアクセスは含まない。
- 表示はゲームとは独立した半透明の最前面ウィンドウ。ゲームのレンダラーにフック・注入しない。
- 既存Go集計エンジン（今回の作業で作成済み）をnative表示でも共用。元MOGUGIの通信デコーダーは使用しない。
- nativeコード: `jp/native_windows.go`（画面・タイマー・設定）、`jp/win32_windows.go`（Windows API）、`jp/session.go`（再生・履歴）、`jp/engine.go`（検証・集計）。`jp/overlay_capture_windows.go`は自分のオーバーレイだけを画像化するQA用処理。
- サンプル専用IDの名前は`jp/config/regions.json`に分離。日本版・台湾版の実ID辞書は空。正式名称・ID・通信形式を推測で補っていない。
- 正規化ログのイベントには一意ID、時刻、攻撃者、対象、スキル、整数ダメージ、クリティカルだけを使う。アカウント情報・認証・生パケットは収集しない。

## 規約と次の工程

日本版の[公式運営ポリシー4-4](https://m.nexon.com/terms/1496)は未承認ソフトウェアの利用等に制限を設けている。受動観測やゲームを改変しない方式でも、承認済みになるとは限らない。この成果物に運営の許可があると主張しない。

実ゲーム接続に進むには、運営から許可されたログ出力・API等の存在と条件、匿名化した仕様・サンプルを確認する。その後に、攻撃者・対象・スキル・クリティカル・パーティ・開始終了を実測値と照合する入力アダプターを実装する。許可された手段がなければ、オフライン分析の範囲を維持する。非認可の通信解析、暗号化・アンチチート回避、メモリ読取・改ざん、コード注入は次工程の代替案にしない。
